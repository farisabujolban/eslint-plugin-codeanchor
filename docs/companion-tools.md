# Companion tools and rule migration

Start with your language lint rules, then add CodeAnchor for repository policies such as issue-linked TODOs, removal conditions for workarounds, and environment variables declared in an example file. Run the [CodeAnchor CLI](https://github.com/farisabujolban/codeanchor) separately for checks that compare repository files or use Git history.

## Replace retired rules

The rules below were removed from both CodeAnchor presets. Delete any explicit `codeanchor/<rule>` settings, overrides, or inline disable comments for them. Install or enable the replacement separately before upgrading if you rely on the check.

| Retired CodeAnchor rule            | Replacement and setup                                                                                                                                                                                                                                                                                                      |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `comment-expiry-date`              | [Unicorn: `expiring-todo-comments`](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/main/docs/rules/expiring-todo-comments.md). Convert dated comments to the bracketed form, such as `TODO [2027-01-15]: ...`. Enable `checkDates` and `checkDatesOnPullRequests`, and include your team's markers in `terms`. |
| `no-array-sort-without-comparator` | [typescript-eslint: `require-array-sort-compare`](https://typescript-eslint.io/rules/require-array-sort-compare/). Enable typed linting and set `ignoreStringArrays: false` to require comparators on string arrays too. The rule checks arrays and typed arrays; it does not flag unrelated methods named `sort`.         |
| `no-double-type-assertion`         | [typescript-eslint: `no-unsafe-type-assertion`](https://typescript-eslint.io/rules/no-unsafe-type-assertion/). Enable typed linting to check narrowing assertions, including unsafe casts through `unknown`.                                                                                                               |
| `no-object-spread-accumulator`     | [Oxlint: `oxc/no-accumulating-spread`](https://oxc.rs/docs/guide/usage/linter/rules/oxc/no-accumulating-spread). Enable this rule explicitly. It checks reducers and loops.                                                                                                                                                |
| `no-process-exit`                  | [eslint-plugin-n: `no-process-exit`](https://github.com/eslint-community/eslint-plugin-n/blob/master/docs/rules/no-process-exit.md). Enable `n/no-process-exit` and use file overrides for CLI entry points that deliberately terminate the process.                                                                       |
| `no-promise-constructor-wrap`      | [eslint-plugin-promise: `avoid-new`](https://github.com/eslint-community/eslint-plugin-promise/blob/main/docs/rules/avoid-new.md). Enable `promise/avoid-new` explicitly. It is stricter: it flags all `new Promise()` calls, so allow intentional constructors where necessary.                                           |
| `require-error-cause`              | [ESLint: `preserve-caught-error`](https://eslint.org/docs/latest/rules/preserve-caught-error). Enable it explicitly on an ESLint version that provides it. Use `errorClassNames` for project-specific error types.                                                                                                         |
